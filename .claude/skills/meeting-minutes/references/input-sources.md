# 입력 계층 — 파일 탐색 확장·어댑터 추가

기본 실행(텍스트 / `--source groq` / `--source whisper`)은 SKILL.md [1]에 있다.
이 문서는 **입력 파일을 못 찾을 때**와 **입력 방식을 새로 붙일 때**만 필요하다.

## 입력 파일 위치 자동 탐색

`<입력>`이 작업 폴더에 없더라도 **파일 이름만** 주면 공통 위치(작업 폴더 → 바탕화면 →
다운로드 → 문서 → 홈)를 재귀 탐색해 찾는다. text/whisper/groq와 양식(.docx)까지 모두
공통 헬퍼 `resolve_input_path`를 쓰므로 동작이 같다.

그래도 못 찾으면 검색한 위치를 안내하며 실패한다. 이때 두 가지 중 하나로 푼다:

- 사용자에게 정확한 경로를 받는다.
- `MEETING_INPUT_DIRS`(os.pathsep 구분) 환경변수로 탐색 루트를 앞쪽에 추가한다.

**탐색이 훑지 않는 곳** — 이유 없이 못 찾는 것처럼 보이면 여기에 해당하는지 본다.
어느 쪽이든 해결책은 같다(정확한 경로 또는 `MEETING_INPUT_DIRS`로 그 폴더를 루트에 추가):

- 루트에서 **6단계보다 깊은** 경로(큰 트리에서 탐색이 폭발하지 않게 둔 한도).
- **숨김 폴더(`.`으로 시작)**와 잡음 폴더 — `AppData`·`Windows`·`Program Files`·
  `node_modules`·`.venv`·`__pycache__`·휴지통 등.

**text 소스에서 파일이냐 원문이냐 구분** — `--source text`는 붙여넣은 원문도 받으므로,
입력이 파일 확장자(`.txt`·`.md`·`.docx`·`.m4a` 등)로 끝날 때만 파일로 취급한다.
그때는 못 찾으면 **실패한다** — 오타 난 파일명이 조용히 "회의 원문 한 줄"이 되어
그걸로 회의록이 만들어지는 사고를 막기 위해서다. 확장자가 없는 한 줄 문자열은
붙여넣은 원문으로 본다.

설치나 키 문제로 STT가 실패했다고 **임의로 다른 소스로 바꿔 실행하지 않는다.**
로컬이냐 클라우드냐는 오디오를 외부로 보내는지의 문제라 사용자가 이미 내린 결정이다.
안내 메시지를 그대로 전달해 설치·설정을 요청한다.

## 입력 어댑터 추가·삭제

- **추가**: `scripts/adapters/`에 `transcribe(source, **opts) -> str`를 구현한 모듈을 만들고
  `scripts/adapters/__init__.py`의 `REGISTRY`에 한 줄 등록.
- **삭제**: `REGISTRY`에서 한 줄 제거 + 모듈 삭제.

어느 쪽이든 [2]~[4] 단계는 수정하지 않는다 — 어댑터가 정규화된 텍스트를 돌려주는 계약만
지키면 하위 단계는 입력 방식을 몰라도 되기 때문이다. 새 입력 방식을 붙이는데 [2]~[4]를
고쳐야 한다면 그 어댑터가 계약을 어기고 있는 것이다.
