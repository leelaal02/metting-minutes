# 회의록 docx 렌더링 고도화 — 설계 (Spec)

- 작성일: 2026-07-27
- 대상 스킬: `.claude/skills/meeting-minutes/`
- 브랜치: `feat/meeting-minutes-skill`
- 상태: **구현 전 실측 리뷰 반영본** (docxtpl 0.20.2 / jinja2 3.1.6 검증)

## 1. 배경 / 문제

STT→추출→양식 채움 파이프라인으로 세 양식(KISA·누리미디어·일반)에 회의록을 채웠으나, 사용자 피드백:

1. 원래 양식에 맞춰 내용이 **제대로** 들어가야 함(정합성).
2. Action Item의 **담당자·기한을 표의 각 컬럼에 자동 채움**. 미지정 시 "입력필요"(빨간 글씨).
3. 논의 **소제목(주제)이 눈에 안 띔** → 넘버링 + 굵게로 가독성 향상(중요).
4. **빈 값 슬롯에 "입력필요"(빨간 굵은 글씨)** — Action Item 표뿐 아니라 **모든 표·모든 미지정 컬럼**에 일괄.
 
## 2. 확정 규칙 (사용자 합의)

- 적용 범위: **스킬 자체 개선**(향후 모든 회의록에 자동 적용) + 기존 3개 파일 재생성.
- "입력필요" 표기: **빨간(FF0000) 굵은 "입력필요"**.
- 소제목(논의 주제): **넘버링 + 굵게**("1. 컨설팅 …").
- **섹션 라벨(논의 내용/결정 사항 등)은 굵게 생략 — 평문 유지**(이미 별도 줄이라 구분됨).
- **"입력필요"는 음성(→minutes.json)에 없는 내용에만.** 데이터가 있으면 그 값을 채우고 절대 "입력필요"로 덮지 않음.
- 음성엔 있으나 9항목 밖 내용 → `notes`(기타·특이사항) 캐치올로 보존.
- 9항목 스키마 **불변**(CLAUDE.md 제약). 양식 전용 라벨칸(장소·작성자·회의장소·첨부 등)은:
  - 원문에 값이 있으면 → `literal`(그 값) 채움.
  - 없으면 → `todo`("입력필요").

## 3. 메커니즘 — docxtpl RichText (실측 검증 결과)

docxtpl `RichText`(색·굵기) + jinja 넘버링을 **렌더 컨텍스트**에서 부여한다. 아래 3개는 실측으로 확인된 **강한 제약**이며 반드시 지킨다.

- **(B1) RichText 토큰은 `{{r ... }}`(r 접두사)로 넣는다.** 일반 `{{ x }}`에 RichText를 주면 `<w:t>` 안에 `<w:r>`이 중첩된 잘못된 XML이 되어 **Word에서 빈칸**으로 표시된다. docxtpl은 `{{r }}` 토큰에만 run 분리를 수행(`template.py:166`).
- **(B2) `{{r }}` 슬롯의 값은 항상 RichText.** 평문 문자열을 `{{r }}`에 주면 **빈칸**으로 렌더된다. 값이 있으면 `R("부장")`, 없으면 `R("입력필요", 빨강·굵게)` — 둘 다 RichText. `RichText.add()`가 `&,<,>`를 내부 escape하므로 특수문자 안전.
- **(B3) 컨텍스트 키 이원화(하위호환).** `build_context`는 **자동매핑 경로와 사용자 작성 토큰 경로가 공유**한다. SKILL.md 치트시트는 사용자에게 `{{ title }}`·`{{ date }}`(일반 토큰)를 안내하므로, 기존 평문 키를 RichText로 바꾸면 사용자 양식이 전부 깨진다. → **평문 키는 그대로 두고, 자동매핑용 RichText 키(`_rt`/`todo`)를 별도 신설**한다.

검증 완료(실측): autoescape=True + `{{r }}` 정상 / `{%tr%}` 행 반복 + gridSpan 병합 셀 보존 / lxml 행 삽입 / 한 문단 내 `{{ }}`+`{{r }}` 혼용 정상.

## 4. 변경 상세

### 4.1 `scripts/render_docx_template.py` — `build_context` 확장 (superset, 하위호환)

```python
from docxtpl import RichText

def _todo():                        # 공통 "입력필요" 빨강·굵게
    rt = RichText(); rt.add("입력필요", color="FF0000", bold=True); return rt

def _rt(value):                     # 값 있으면 평문 RichText, 없으면 todo
    rt = RichText()
    if value not in (None, "", []):
        rt.add(str(value))
    else:
        rt.add("입력필요", color="FF0000", bold=True)
    return rt

def _topic_rt(i, topic):            # "N. 주제" 굵게 (넘버링+굵게)
    rt = RichText(); rt.add(f"{i}. {topic}", bold=True); return rt
```

컨텍스트는 **평문 키(기존 유지) + RichText 키(신설)** 를 모두 담는 superset:

```python
return {
    # --- 평문 키: 사용자 {{ }} 토큰 경로 (무변경, 하위호환) ---
    "title": data["title"],
    "date": data.get("date") or "",
    "purpose": data.get("purpose") or "",
    "next_meeting": data.get("next_meeting") or "",
    "attendees": data["attendees"],
    "attendees_joined": ", ".join(data["attendees"]),
    "discussion": data["discussion"],
    "decisions": data["decisions"],
    "action_items": [{"task": a["task"], "owner": a["owner"] or "-",
                      "due": a["due"] or "-"} for a in data["action_items"]],
    "notes": data["notes"],

    # --- RichText 키: 자동매핑 {{r }} 경로 (신설) ---
    "todo": _todo(),
    "title_rt": _rt(data["title"]),
    "date_rt": _rt(data.get("date")),
    "purpose_rt": _rt(data.get("purpose")),
    "next_meeting_rt": _rt(data.get("next_meeting")),
    "attendees_rt": _rt(", ".join(data["attendees"]) if data["attendees"] else None),
    # 원본 불변: 새 리스트를 만든다 (data mutation 금지)
    "discussion_rt": [{"topic_rt": _topic_rt(i, d["topic"]), "points": d["points"]}
                      for i, d in enumerate(data["discussion"], 1)],
    "action_items_rt": [{"task": a["task"], "owner_rt": _rt(a["owner"]),
                         "due_rt": _rt(a["due"])} for a in data["action_items"]],
}
```

- **섹션 라벨용 `label_*` 키는 만들지 않는다**(라벨 굵게 생략 확정).
- autoescape=True 유지(평문 값의 `&,<,>` 보존). RichText는 자체 escape.

### 4.2 `scripts/apply_form_mapping.py` — 토큰/모드 확장

**스칼라 토큰을 `{{r *_rt }}`로 교체** (자동매핑이 생성하는 토큰만; 사용자 치트시트 `{{ }}`는 불변):
```python
_SCALAR_TOKEN = {
    "title": "{{r title_rt }}", "date": "{{r date_rt }}",
    "attendees": "{{r attendees_rt }}", "purpose": "{{r purpose_rt }}",
    "next_meeting": "{{r next_meeting_rt }}",
}
```

**목록형 블록** — discussion은 넘버링+굵게, action_items는 owner/due를 `{{r }}`로:
```python
_LIST_BLOCK = {
  "discussion": ["{%p for d in discussion_rt %}", "{{r d.topic_rt }}",
                 "{%p for p in d.points %}", " - {{ p }}", "{%p endfor %}", "{%p endfor %}"],
  "decisions":  ["{%p for x in decisions %}", " - {{ x }}", "{%p endfor %}"],
  "action_items":["{%p for a in action_items_rt %}",
                  " - {{ a.task }} (담당: {{r a.owner_rt }} / 기한: {{r a.due_rt }})",
                  "{%p endfor %}"],
  "notes":      ["{%p for n in notes %}", " - {{ n }}", "{%p endfor %}"],
}
```
- 섹션 라벨(`_SECTION_LABEL`)은 **평문 유지**("[논의 내용]" 등, 굵게 없음).
- 목록 항목 본문(`points`,`decisions`,`notes`,`task`)은 항상 존재 → **평문 `{{ }}`**(autoescape로 안전).

**새 모드 3종**
- `todo`: 대상 칸/문단에 `{{r todo }}` 삽입(라벨 있으면 뒤에 append, 빈칸이면 첫 문단). fields 불필요.
- `literal`: 대상에 `text`(매핑에 명시)를 **평문 run**으로 삽입(원문에서 찾은 값). fields 대신 `text` 키.
- `table_rows`(행 반복 표, **일반 기능**): 리스트형 필드를 `{%tr%}`로 표의 행에 펼침.
  - 매핑: `{"mode":"table_rows","table":1,"row":2,"field":"action_items","cols":{"task":0,"due":3,"owner":4}}`
  - 동작: `row`(데이터 행)의 각 컬럼에 하위필드 토큰을 넣고(task=평문 `{{ a.task }}`, owner/due=`{{r a.owner_rt }}`/`{{r a.due_rt }}`), 반복은 `action_items_rt` 대상. 데이터 행 XML을 **deepcopy**해 셀을 비우고 태그만 넣은 **for행/endfor행**을 앞뒤(lxml `addprevious`/`addnext`)에 삽입 → 정확히 3행 구조. gridSpan 병합 폭 유지됨(실측).
  - 렌더 시 docxtpl가 데이터 행을 항목 수만큼 반복, 태그 행은 삭제.

### 4.3 매핑 판단 규칙 (SKILL.md에 명문화)

- **리스트형 자리가 "행 반복 표(컬럼 구조)"면 `table_rows`**, 단일 칸·문단이면 `block`.
- 스칼라 라벨칸은 `inline`(값) 또는 `todo`(데이터 없음)/`literal`(원문 값).
- → 어떤 새 양식이 와도 **구조 기준**으로 동일하게 처리(특정 양식 하드코딩 아님).

### 4.4 매핑 3종 갱신 (원문 재확인: 장소·작성자·회의장소·첨부·다음회의 음성에 없음 → `todo`)

- **KISA**: 장소(r3c0)·소속/성명·직급(r3c1) → `todo`. 실행항목은 향후계획 블록(owner/due 없으면 컬럼 아닌 텍스트 "입력필요").
- **누리미디어**: t0 작성자(r0c3)·회의장소(r1c3) → `todo`. t1 action_items → `table_rows`(task=c0, due=c3, owner=c4), 미결사항(r4c2)·다음회의(r6)·첨부(r7c1) → `todo`.
- **일반 양식**: ㅇ (장소)(para5) → `todo`.

### 4.5 산출물 위치 규칙 준수

중간 파일(`*_tokenized.docx`, 매핑)은 `output/.work/`, 최종 3종 docx만 `output/`.

## 5. 테스트 (`tests/`)

- **회귀(최우선):** 사용자 `{{ date }}`·`{{ title }}` 평문 토큰 양식이 여전히 정상 렌더(B3 보호).
- 빈 스칼라 → 빨간 "입력필요" 런(FF0000·bold), 값 있으면 평문(빨강 아님).
- discussion topic → "1. …" 굵게(넘버링 리셋 1부터).
- action owner/due: `block`(텍스트)·`table_rows`(컬럼) 양쪽에서 값→평문 / 없음→빨강.
- `table_rows`: 결과 행수=항목수, gridSpan 보존, for/endfor 행 제거.
- 특수문자(`R&D`,`<A>`) 보존.
- `apply_form_mapping` 토큰 문자열 변경에 맞춰 기존 `test_apply_form_mapping.py` 기대값 갱신.

## 6. 리스크 / 주의

- **값 서식 정합(폰트):** `{{r }}`가 만든 값 run은 **색·굵기만 적용되고 라벨의 폰트(서체·크기)는 상속하지 않음**(실측). 템플릿마다 폰트가 달라 일반화가 어려우므로 **문서 기본 폰트 수용**(의도된 절충; 가독성엔 지장 없음).
- `table_rows`는 표 XML을 직접 조작하는 **유일한 침습적 경로** → 별도 함수로 격리하고 집중 테스트. 태그 행은 데이터 행 deepcopy로 셀 수(gridSpan 포함) 유지.
- 병합 셀 좌표는 원점(merged origin) 기준(기존과 동일).
- Markdown-우선 순서 유지. 단 넘버링/굵게는 **docx에만** 반영(검토용 md와 표현 차이 — 의도됨).
- `literal` 값은 mapping.json에서 옴 → docx 내용 일부가 minutes.json 밖. 소량·판단 필요분에 한정(문서화).

## 7. 원래 설계 vs 수정 방향 (리뷰 반영, 정정본)

| # | 항목 | 원래 설계 | 수정 방향 | 이유 |
|---|---|---|---|---|
| 1 | 서식 토큰 문법 | `{{ date }}`,`{{ todo }}`(일반) | `{{r date_rt }}`,`{{r todo }}`(**r 접두사**) | 일반 토큰+RichText는 run 중첩 → 빈칸(B1) |
| 2 | 값의 타입 | 있으면 평문 str, 없으면 RichText | **항상 RichText** | `{{r }}`에 평문 → 빈칸(B2) |
| 3 | 컨텍스트 키 | 기존 키를 RichText로 덮어씀 | 평문 키 유지 + `_rt`/`todo` **신설**(이원화) | 덮으면 사용자 `{{ date }}` 깨짐(B3) |
| 4 | 사용자 토큰 양식 호환 | (고려 안 함 → 파손) | **무손상** | 치트시트 `{{ title }}` 보존 |
| 5 | 섹션 라벨 | RichText 굵게 | **굵게 생략, 평문 유지** | 이미 별도 줄; 단순화 |
| 6 | 값 서식 정합 | (논의 중 제안) 라벨 rPr 복사 | 색·굵기만 적용, **폰트는 문서 기본 수용** | 값 run이 라벨 폰트 상속 안 함(실측) |
| 7 | Action Item 컬럼 | Action Item 표 전용 `table_rows`(누리미디어) | **리스트×행반복 표 일반 규칙**(현재 인스턴스=컬럼형 Action Item 표) | 구조 기준 범용화; 표 없으면 block |
| 8 | discussion 처리 | `data` dict에 `topic_rt` 주입 | **새 리스트(`discussion_rt`) 생성**(원본 불변) | 부작용 차단 |
| 9 | 테스트 | 신규 기능 테스트 | + **회귀 테스트(사용자 `{{ }}` 양식)** 최우선 | B3 보호 |
| 10 | 양식 전용 라벨(장소·작성자) | (없음) | `literal`(원문 값) / `todo`(없음) | 음성 유무 규칙 준수 |
| 11 | 매핑 판단 규칙 | (암묵) | SKILL.md 명문화("행반복 표→table_rows, 아니면 block") | 새 양식 일관 처리 |

## 8. 완료 기준 (Acceptance)

1. 세 양식 모두 데이터 있는 곳은 정확히 채우고, 음성에 없는 값 슬롯은 전부 빨간 굵은 "입력필요".
2. 누리미디어 Action Item이 담당자·기한 컬럼으로 분리 채움, 기한 없으면 컬럼에 "입력필요".
3. 논의 소제목이 "1. …/2. …" 넘버링+굵게.
4. 채워진 값 위에 "입력필요"가 덮이지 않음.
5. 사용자 `{{ }}` 토큰 양식(has_tokens) 회귀 정상.
6. `pytest` 통과.
