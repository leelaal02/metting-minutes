# 회의록 docx 렌더링 고도화 — 설계 & 실측 리뷰 정리

> 대상: `.claude/skills/meeting-minutes/` · 브랜치 `feat/meeting-minutes-skill` · 2026-07-27
> 상태: **구현 전 설계 확정 (docxtpl 0.20.2 / jinja2 3.1.6 실측 검증 완료)**

## TL;DR

- 회의록 docx에 **① 빈 값 슬롯 빨간 "입력필요" ② 논의 소제목 넘버링+굵게 ③ Action Item 담당/기한 컬럼 채움**을 스킬 자체에 추가한다.
- 구현 핵심은 서식이 아니라 **배관**: docxtpl RichText를 `{{r }}` 문법 + 항상 RichText + 컨텍스트 이원화로 넣어야 한다. (안 그러면 **조용히 빈칸으로 깨짐** — 실측 확인)
- "입력필요"는 **음성에 없는 값에만** 붙는다. 있으면 그대로 채운다. 9항목 스키마는 불변.

---

## 1. 요구사항 (사용자 피드백)

1. 원래 양식에 맞춰 내용이 **제대로** 입력 (정합성)
2. Action Item **담당자·기한을 컬럼에 자동 채움**, 미지정 시 "입력필요"(빨간 글씨)
3. 논의 **소제목이 눈에 안 띔** → 넘버링/굵게로 가독성 향상 *(중요)*
4. **빈 값 슬롯에 빨간 "입력필요"** — 모든 표·모든 미지정 컬럼 일괄

## 2. 확정 규칙

| 항목 | 결정 |
|---|---|
| 적용 범위 | 스킬 자체 개선 (향후 전체 자동 적용) + 기존 3개 파일 재생성 |
| "입력필요" | 빨강(FF0000) **굵게** |
| 소제목(논의 주제) | 넘버링 + 굵게 ("1. 컨설팅 …") |
| 섹션 라벨(논의 내용 등) | 굵게 **생략**, 평문 유지 |
| "입력필요" 조건 | **음성(minutes.json)에 없는 값에만**. 있으면 덮지 않음 |
| 9항목 밖 음성 내용 | `notes`(기타·특이사항)로 보존 |
| 양식 전용 라벨(장소·작성자 등) | 원문에 있으면 `literal`(값), 없으면 `todo`(입력필요) |
| 스키마 | 9항목 **불변** |

## 3. 핵심 발견 — 반드시 지켜야 할 제약 (실측)

| 코드 | 발견 | 안 지키면 |
|---|---|---|
| **B1** | RichText는 `{{r ... }}`(r 접두사)로 넣어야 함 | 일반 `{{ }}`+RichText → `<w:t>` 안에 run 중첩(invalid) → **Word에서 빈칸** |
| **B2** | `{{r }}` 슬롯 값은 **항상 RichText** (있으면 `R("부장")`, 없으면 `R("입력필요",빨강)`) | 평문 문자열을 `{{r }}`에 넣으면 **빈칸** |
| **B3** | 컨텍스트 키 **이원화** (평문 키 유지 + `_rt`/`todo` 신설) | 기존 키를 RichText로 덮으면 사용자 `{{ date }}` 양식 **전부 깨짐** |

> docxtpl은 `{{r }}` 토큰에만 run 분리를 수행(`template.py:166`). `RichText.add()`가 `& < >`를 내부 escape하므로 특수문자는 안전.

## 5. 변경 요약 (파일별)

**`render_docx_template.py` — `build_context` (superset, 하위호환)**
```python
def _todo():                # "입력필요" 빨강·굵게
    rt = RichText(); rt.add("입력필요", color="FF0000", bold=True); return rt
def _rt(value):             # 값 있으면 평문 RichText, 없으면 todo
    rt = RichText()
    rt.add(str(value)) if value not in (None,"",[]) else rt.add("입력필요", color="FF0000", bold=True)
    return rt
def _topic_rt(i, topic):    # "N. 주제" 굵게
    rt = RichText(); rt.add(f"{i}. {topic}", bold=True); return rt
```
- 평문 키(title/date/… 기존) **그대로** + RichText 키(`todo`,`*_rt`,`discussion_rt`,`action_items_rt`) 신설
- `discussion_rt`는 **새 리스트**로 생성(원본 dict 변형 금지)

**`apply_form_mapping.py` — 토큰/모드 확장**
- 스칼라 토큰 → `{{r title_rt }}`,`{{r date_rt }}` … (자동매핑 생성분만; 사용자 치트시트 `{{ }}` 불변)
- discussion 블록 → `{{r d.topic_rt }}`(넘버링+굵게), action_items 블록 → `{{r a.owner_rt }}`/`{{r a.due_rt }}`
- 섹션 라벨은 평문 유지
- **새 모드 3종:**
  - `todo` — 빈 값칸에 `{{r todo }}`
  - `literal` — 원문에서 찾은 값을 평문으로 삽입 (`text` 키)
  - `table_rows` — 리스트형을 `{%tr%}` 행 반복으로 컬럼 채움

**매핑 3종 갱신** (원문 재확인: 장소·작성자·회의장소·첨부·다음회의 음성에 없음 → `todo`)
| 양식 | 실행항목 | 빈칸 처리 |
|---|---|---|
| KISA | block(단일 칸) | 장소·소속 → todo |
| 누리미디어 | **table_rows**(컬럼표) | 작성자·회의장소·미결·다음회의·첨부 → todo |
| 일반 양식 | block(문단) | 장소 → todo |

## 6. 원래 설계 vs 수정 방향

| # | 항목 | 원래 | 수정 | 이유 |
|---|---|---|---|---|
| 1 | 토큰 문법 | `{{ date }}` | `{{r date_rt }}` | run 중첩 → 빈칸 (B1) |
| 2 | 값 타입 | 있으면 str, 없으면 RichText | **항상 RichText** | `{{r }}`+평문 → 빈칸 (B2) |
| 3 | 컨텍스트 키 | 기존 키 덮어씀 | 평문 유지 + `_rt`/`todo` 신설 | 사용자 양식 깨짐 (B3) |
| 4 | 사용자 양식 호환 | 파손 | **무손상** | 치트시트 보존 |
| 5 | 섹션 라벨 | 굵게 | **평문 유지** | 이미 별도 줄; 단순화 |
| 6 | 값 서식 정합 | (제안)라벨 폰트 복사 | 색·굵기만, **폰트 문서 기본** | 값 run이 라벨 폰트 상속 안 함 |
| 7 | Action Item 컬럼 | Action Item 전용(누리) | **리스트×행반복 표 일반 규칙** | 구조 기준 범용화 |
| 8 | discussion | data dict에 주입 | **새 리스트 생성** | 부작용 차단 |
| 9 | 테스트 | 신규 기능 | + **회귀(사용자 `{{ }}`)** 최우선 | B3 보호 |
| 10 | 양식 전용 라벨 | (없음) | `literal`/`todo` | 음성 유무 규칙 |
| 11 | 매핑 판단 규칙 | 암묵 | **SKILL.md 명문화** | 새 양식 일관 |

## 7. 매핑 판단 규칙 (구조 기준 · SKILL.md 반영)

| 데이터 | 양식 자리 | 방식 |
|---|---|---|
| 리스트형(action_items, decisions, notes…) | **행 반복 표(컬럼)** | `table_rows` |
| 리스트형 | 단일 칸 / 문단 | `block` |
| 스칼라형(title, date…) | 라벨칸 | `inline`(값) / `todo`(없음) / `literal`(원문값) |

> 특정 양식 하드코딩 아님 — 새 양식도 구조로 자동 판단. 현재 컬럼형 표는 누리미디어 Action Item뿐.

## 9. 리스크 / 주의

- **폰트 정합:** `{{r }}` 값 run은 색·굵기만 적용, 라벨 폰트(서체·크기) 상속 안 함 → 문서 기본 폰트 수용(절충)
- `table_rows`는 표 XML 직접 조작하는 유일 침습 경로 → 별도 함수 격리 + 집중 테스트
- Markdown-우선 순서 유지, 단 넘버링/굵게는 docx에만(검토 md와 표현 차이 — 의도)
- `literal` 값은 mapping.json에서 옴 → 소량·판단분에 한정(문서화)
